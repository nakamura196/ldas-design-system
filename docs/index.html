書体・余白・最大幅

Foundation / Layout

推奨（Do）

  • 最大幅は 1280px（max-w-7xl） を基本にする
  • 書体は BIZ UDPGothic（または Noto Sans JP）
  • 角丸は 4px〜6px（rounded-md〜rounded-lg）に抑える

避ける（Don't）

  • グラデーション背景・ドット柄・光るぼかし円（blur-3xl）
  • 過度な角丸（rounded-2xl）や大きなドロップシャドウ
  • 大文字英語の飾り見出し（例: 01 / FEATURE）

情報設計の原則（1 画面 1 目的・詰め込み禁止）

Foundation / IA

AI に機能追加を頼み続けると、1 ページにカード・ボタン・説明が凝縮して「何をする画面か分からない」状態になりやすい。GOV.UK の One thing per page に倣い、役割ごとに URL パスを分割します。

推奨（Do）

  • 役割ごとに URL パスを分ける（例: /account・/provider・/admin/providers）
  • 主ボタン（青塗り）は 1 セクションに 1 つだけにする
  • 管理者専用・開発者用リンクは一般画面に混ぜない
  • 説明文は 1〜2 文に収め、見出しと項目名で伝える

避ける（Don't）

  • 1 ページの中に「設定・申請・一覧・管理・API 例」を全部縦積みする
  • 同じ URL のままタブ切り替えだけで無関係な機能を隠す
  • 未ログイン状態でもダミー金額や他ユーザーの履歴を表示する

アクセシビリティ基準（デジタル庁・GOV.UK 準拠）

Foundation / A11y
フォーカス表示 Tab キー移動時に 3px solid #ffcd00（UTokyo Yellow）の明確なフォーカスリングを表示し、背景色と紛れないようにする。
色だけに頼らない 状態（公開中／停止中／要認証）は色だけでなく、必ず日本語テキストで明記する。
ランドマークと操作性 <header>・<nav>・<main>・<footer> を使い分け、クリック可能要素は必ず <a> または <button> にする。

Component / Navigation

いつ使うか（When to use）

  • 全ページ共通の上部ナビゲーション（4〜5 項目以内）
  • 検索画面やトップページの導入となる単色タイトル帯

いつ使わないか（When not to use）

  • ページごとにヘッダー項目を増減させない
  • ヘッダー内に派手な丸ボタンやバッジを並べない

管理画面パターン（左サイドバー＋機能別 URL）

Pattern / Admin

dataspace.ldas.jp/admin/* や archivebase のような管理画面では、左側に固定幅メニュー（各項目が独立した URL パス）、右側に 1 目的のワークスペースを配置します。
